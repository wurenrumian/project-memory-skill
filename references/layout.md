# 目录结构（权威定义）

项目根下的 `./tmp/` 是这份记忆的唯一根。

```
./tmp/
├── README.md            # 这目录是什么、"顶层不可随意删"的约定、入口指引（人读一次）
├── STATE.md             # 【必读】当前状态 / 进行中 / 下一步 / 待决 / 关键链接
├── journal/
│   └── 2026-09-27.md    # 追加式时间线，一天（或一会话）一个文件
├── docs/                # 沉淀后的稳定内容
│   ├── memory/          # 项目记忆：决策、架构、约定、踩过的坑
│   ├── research/        # 研究讲解 / 分析长文 / 论文笔记
│   └── plans/           # 方案草案、路线图、待验证想法
├── experiments/         # 实验的「定义与结论」——小、稳定、人读
│   └── EXP-0001-slug/
│       ├── README.md    # 问题/假设/方法/结果/结论/未决
│       ├── config.yaml   # 该实验固定参数
│       └── scripts/      # 实验专属脚本（可复用时才提升到顶层 scripts/）
├── outputs/             # 所有程序产物；内部结构自定，不设约定（默认整个 gitignore）
├── annotated/           # 需着重讲解/强调的代码：讲解 md 或带注释的源码片段
│   └── <topic-slug>     # 单文件 .md/.<ext> 或目录，形态自由（见 conventions）
├── show/                # 给人展示/讲解的成品（slides、图、demo）
│   └── <topic-slug>/
├── scripts/             # 跨实验复用的工具
├── scratch/             # 真正的草稿，允许随时删
└── archive/             # 完成/废弃的东西移到这里，不删
```

## 为什么产物独立于实验

实验**定义**和运行**产物**的生命周期相反：

| | 实验定义（`experiments/`） | 运行产物（`outputs/`） |
|---|---|---|
| 数量 | 少 | 多 |
| 变化 | 稳定 | 只增不减 |
| 体积 | 小 | 可能巨大 |
| 谁读 | 人 | 脚本写、人偶尔查 |

所以：**产物写进固定的 `outputs/` 根，不写进 `experiments/`。** 这样大文件集中可清理、把实验归档时不会漏掉或误带一堆数据。

### outputs 里不设约定

`outputs/` 就是一个"往里放"的根：**内部结构完全由产生它的程序决定**，skill 不规定分组、命名，也不要求必须有哪些文件。程序最清楚自己的产物长什么样，硬套一层目录只会碍事。

代价是：从产物反推属于哪个实验要另找线索。所以纪律放在"写它的人"这边——开实验 / 跑完时，在实验 `README.md` 或当天 `journal/` 记一行产物位置就行，不必回头维护 `outputs/` 内部。

## 各条目一览（按生命周期分组）

同一组里的东西，对待方式一样——这是记住这套结构的捷径。

| 条目 | 作用 | 谁来写 · 何时 | 不装什么 |
|---|---|---|---|
| **入口** | | | |
| `STATE.md` | 唯一入口：现在 / 进行中 / 下一步 / 待决 / 关键链接 | 每次收尾，覆盖更新 | 知识本身、细节 |
| `README.md` | 声明这目录是记忆、列目录与约定 | 初始化一次 | —— |
| **只增不改** | | | |
| `journal/` | 追加式时间线，一天一个文件 | 随手记 | 排版好的长文 |
| `outputs/` | 程序产物，内部结构自定（整块 gitignore） | 程序 | 实验定义、配置 |
| `archive/` | 完成 / 废弃的东西，移进来不删 | 收尾、放弃时 | 仍在进行的工作 |
| **少而稳定** | | | |
| `experiments/` | 实验的定义与结论（问题→结论、config、专属脚本） | 开实验时 | 运行产物 |
| `scripts/` | 跨实验复用的工具 | 出现第二次复用时 | 单个实验专用的脚本 |
| **稳定后沉淀** | | | |
| `docs/` | 时间脱钩、会被人回头查的知识 | 结论稳定时 | 日志、运行输出 |
| `annotated/` | 围绕代码的讲解（md / 带注释源码片段） | 想讲清某段代码时 | 日常源码 |
| `show/` | 面向展示场合的成品（slides / 图 / demo） | 准备演示时 | 参考文档 |
| **可丢** | | | |
| `scratch/` | 草稿、一次性文件 | 随手 | 任何想留的东西 |

## 五条容易搞错的事

1. **产物不进 `experiments/`，一律进 `outputs/`。** 内部怎么组织由程序决定。
2. **实验专属脚本放实验目录里，不放 `scripts/`。** 只有被第二个实验复用时才提升到 `scripts/`。
3. **`annotated/` 里的代码要记来源**（原路径 + commit/日期），否则会和真实源码漂移，久了就变成假的。
4. **`docs/`、`annotated/`、`show/` 三者的区别是"读者在什么状态读"**：`docs/` 是随时查的参考，`annotated/` 是围着代码讲实现，`show/` 是在一个展示场合讲给他人听。拿不准就问一句"这东西是给谁、在什么场合用的"。
5. **`scratch/` 是唯一可任意删除的区域。** 其他顶层目录都受 `./tmp/README.md` 的"不可随意删"约定保护。
